# 04 训练

训练把"51 条（或 40 条）示教"压成一个神经网络。整个过程不需要你调参，需要你判断的是：
**数据对不对、显存够不够、最后选哪个权重**。

---

## 一、训练在学什么（一句话版）

> 输入：两路相机画面 + 当前 14 维关节角
> 输出：未来 32 帧（约 1 秒）的 14 维目标关节角

模型结构（ACT，不用改）：

```
cam_high 480×640 ─┐
                  ├→ ResNet18 ─┐
cam_right_wrist ──┘            ├→ Transformer 编码器(4层) → 解码器(7层) → 32×14 动作块
qpos (14维) ───────────────────┘
                 ↑ 训练时还有一条 CVAE 隐变量分支（kl_weight=10），推理时取先验
```

推理时模型每帧都会重新预测一个 32 帧的动作块，再用**时间集成**（指数加权，`exp(-0.01·i)`）
把历史预测平滑在一起，所以实际下发的是"平滑后的当前帧目标"。

## 三、一键训练（推荐）

```bash
bash ~/cobot_magic/train_cube.sh [任务名] [训练目录] [epochs] [batch]

# 例：用现有的固定位置数据重训一份（不改任何东西，验证流程）
bash ~/cobot_magic/train_cube.sh grasp_cube ~/train_cube_v4 3000 8

# 例：训练随机位置数据集（采完 40 条之后）
bash ~/cobot_magic/train_cube.sh grasp_cube_rand ~/train_cube_rand 3000 8
```

脚本会依次：

1. 数 `~/data/<任务名>/episode_*.hdf5` 的条数（必须和真实条数一致，见第四节）
2. 先跑一遍质检，有不合格条目直接拒绝开训（`SKIP_CHECK=1` 可跳过）
3. 训练目录已存在且有权重时拒绝覆盖（`FORCE=1` 可强制）
4. 后台训练，日志同时写到 `<训练目录>/train_<时间>.log`
5. 结束后打印下一步（离线评估 + 推理命令）

**长时间训练一定要后台跑**，否则关终端/断 SSH 就没了：

```bash
mkdir -p /tmp/aloha_logs
setsid nohup bash ~/cobot_magic/train_cube.sh grasp_cube_rand ~/train_cube_rand 3000 8 \
    > /tmp/aloha_logs/train_rand.log 2>&1 < /dev/null &

# 看进度
tail -f ~/train_cube_rand/train_*.log
```

> 为什么强调 `setsid nohup`：之前有一次训练跑到 epoch 2249 就凭空消失，日志里既没有报错也没有 OOM，
> 就是进程被会话清理带走了。`setsid` 让它彻底脱离终端。

## 四、手工命令（想知道脚本背后是什么）

```bash
cd ~/cobot_magic/aloha-devel
export PYTHONPATH=$PWD:/opt/ros/noetic/lib/python3/dist-packages
export MPLBACKEND=Agg

/home/agilex/miniconda3/envs/aloha/bin/python act/train.py \
    --dataset_dir ~/data \
    --task_name grasp_cube \
    --ckpt_dir ~/train_cube_v4 \
    --num_episodes 51 \
    --num_epochs 3000 \
    --batch_size 8
```

### 两个必须注意的语义（踩过坑）

1. **`--dataset_dir` 是父目录，不是任务目录**。
   实际读取的是 `--dataset_dir/<--task_name>`。
   `--dataset_dir ~/data --task_name grasp_cube` → 读 `~/data/grasp_cube` ✓
   `--dataset_dir ~/data/grasp_cube` → 会去找 `~/data/grasp_cube/grasp_cube` ✗
2. **`--num_episodes` 必须等于真实条数**。
   代码按 `0..N-1` 生成索引去读文件（`np.random.permutation(N)`）。
   写多了 → 读不到文件报错；写少了 → 后面的条数直接不参与训练，你还是"少训了一部分数据"却不报错。

### 关键超参（本任务的取值）

| 参数 | 值 | 说明 |
|------|----|------|
| `--policy_class` | ACT | 别改 |
| `--backbone` | resnet18 | ImageNet 预训练，改大会爆显存 |
| `--chunk_size` | 32 | 一次预测 32 帧 ≈ 1.07 s；太小动作抖，太大反应慢 |
| `--kl_weight` | 10 | CVAE 权重 |
| `--lr` / `--lr_backbone` | 4e-5 | |
| `--weight_decay` | 1e-4 | |
| `--loss_function` | l1 | |
| `--batch_size` | **8** | 8 GB 显存下稳定；爆显存就降到 4 |
| `--num_epochs` | 3000 | 本任务 2000 左右就基本收敛 |
| `--enc_layers` / `--dec_layers` | 4 / 7 | |
| `--hidden_dim` / `--dim_feedforward` | 512 / 3200 | |
| `--temporal_agg` | True | 推理时用，训练无影响 |

## 五、训练过程会发生什么

1. **计算归一化统计** → 存成 `<ckpt_dir>/dataset_stats.pkl`
   （`qpos_mean/std`、`action_mean/std`，各 14 维；还有一条 `example_qpos` 样例轨迹）
2. **按"条"随机 8:2 分训练/验证**（51 条 → 约 41 训练 / 10 验证；因为 `set_seed(1)`，划分是固定的）
3. 每个 epoch = 把训练集过一遍（一个样本 = 一条 episode 里的一段 chunk）
4. **每 100 epoch 存一个权重** `policy_epoch_N_seed_0.ckpt`（380 MB）
5. 训练中每次验证 loss 创新低都会记下 best；结束存 `policy_best.ckpt`，最后再存 `policy_last.ckpt`
6. 画三条曲线：`train_val_loss_*.png`、`train_val_l1_*.png`、`train_val_kl_*.png`

**速度**：本机 RTX 4060、51 条、batch 8 → 约 **2.5 秒/epoch**，3000 epoch ≈ **2 小时**。
40 条会更快一点（约 1.7 小时）。

**磁盘**：3000 epoch 会存 30 个权重 ≈ **11 GB**。定期清理，只留你要用的几个：

```bash
# 只保留 500 的倍数和 2100（举例）
cd ~/train_cube_rand
ls policy_epoch_*.ckpt | grep -vE "_(1000|1500|2000|2100|2500|3000)_" | xargs -r rm -v
```

## 六、怎么判断训练是否正常

看日志：

```
Epoch 1000
Val loss:   0.13599
l1: 0.133 kl: 0.003 loss: 0.136
Train loss: 0.12904
```

v3 的真实收敛过程（51 条，3000 epoch 计划）：

| epoch | 验证 loss |
|-------|-----------|
| 100 | 0.595 |
| 500 | 0.184 |
| 1000 | 0.136 |
| 1500 | 0.102 |
| 2000 | **0.084**（最低点附近） |
| 2200 | 0.198（验证集只有 10 条，噪声大） |
| 2249 | 0.151（当时被中断的位置） |

判断方法：

- 应该从 0.5~0.9 一路降到 **0.08~0.15**；完全不降 → 数据/归一化有问题（先看是不是主臂没上电）
- 验证 loss 忽高忽低是**正常**的：验证集只有 20% 的条数（51 条 → 10 条），
  一次验证只有 2 个 batch，噪声很大。**看趋势，不要盯单个 epoch。**
- 这个 loss 是"归一化后动作"的 L1（再加 KL 项），**不是弧度**，不能直接换算成厘米。
  想知道真实误差，用 `eval_ckpt.py`（第七节）。
- 训练 loss 和验证 loss 差很多（如 0.02 vs 0.06）→ 过拟合，说明数据太少或太单一

曲线在 `train_val_loss_seed_0.png`（总）、`train_val_l1_seed_0.png`、`train_val_kl_seed_0.png`。

## 七、选权重：离线先筛，再上机

### 1) 离线评估（不用机械臂）

```bash
/home/agilex/miniconda3/envs/aloha/bin/python ~/cobot_magic/eval_ckpt.py \
    --ckpt ~/train_cube_v3/policy_epoch_2100_seed_0.ckpt \
    --stats_dir ~/train_cube_v3 \
    --episodes 0,10,25,40,50
```

它在**录好的观测**上逐帧推理，把预测动作和示教动作对比，输出：

- 右臂 6 轴 MAE（rad）——最关键的指标
- 左臂 MAE（应该很小，因为左臂不动）
- 夹爪 MAE
- 夹爪"张开/夹住/释放"事件的时间差（预测比示教早/晚几帧）

参考值（v3 实测）：

| 权重 | 右臂 MAE | 右夹爪 MAE | 左臂 MAE |
|------|----------|-----------|----------|
| epoch 2100 | **0.0549 rad** | 0.0064 | 0.013 |
| epoch 2200 | 0.0608 rad | 0.0065 | 0.013 |

右臂 MAE 0.055 rad ≈ 末端 1.1 cm 的偏差——这就是"只能在固定位置抓"的量化来源。

### 2) 上机验证

离线好的权重再上机（`docs/05`），看两件事：

- 能不能夹住（日志里实测夹爪到 0.023~0.028）
- 能不能在盒子处松手（日志出现 `🔓 到位释放` 或模型自己给释放峰）

**经验**：离线 MAE 相差 0.005 rad 以内基本肉眼看不出差别，别为了 0.003 的差距纠结几百个 epoch。

## 八、实验记录（本机真实数据）

| 版本 | 数据 | 结果 / 结论 |
|------|------|------------|
| v1 | 早期少量数据 | 基本不可用（数据规范没建立） |
| v2 | 固定位置 | 能抓，但夹爪不会松手（后来靠两态化+兜底修好） |
| v3 | 51 条 × 400 帧 | 固定位置稳定成功；离线 2100 最优；连续循环第 2 轮起姿态漂移 |
| 下一步 | 40 条 10 cm 随机位置 | 目标：方块位置变化也能抓 |

**v3 的关键教训**：51 条示教里，夹住瞬间右臂 6 轴标准差只有 0.064 rad（末端 ±1.3 cm）。
数据里没有"位置变化"，模型数学上学不出泛化——这不是网络容量问题，是数据问题。

## 十、训练故障

| 现象 | 原因 / 处理 |
|------|------------|
| `CUDA out of memory` | 降 `--batch_size 4`；关掉别的占显存程序（`nvidia-smi`） |
| 进程跑到一半消失，日志无报错 | 被会话清理。用 `setsid nohup`；或查 `dmesg -T | grep -i oom` 确认是否被系统杀 |
| `FileNotFoundError: .../episode_XX.hdf5` | `--num_episodes` 比真实条数大 |
| loss 一直 0.1 以上不降 | 数据里 `action` 和 `qpos` 搞混（主臂没上电）、或归一化 std 被野值压扁（跑质检） |
| 训练很慢（>10 s/epoch） | 有人在用 GPU / 数据在机械硬盘 / batch 太大 |
| 曲线图没生成 | `MPLBACKEND` 没设成 `Agg` |
