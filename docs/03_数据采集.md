# 03 数据采集

采集是整套流程里**最影响上限**的一步。策略能做的事，本质上是"示教里出现过的事"——
示教里方块永远在同一个点，策略就只会去那一个点抓（当前版本就卡在这里）。

---

## 一、采集程序在做什么

`collect_data.py` 以 **30 Hz** 循环，每一帧存一组：

| 存的东西 | 来源 | 在 HDF5 里 |
|----------|------|-----------|
| 头视彩色图 | `/camera_r` | `observations/images/cam_high` |
| 右腕彩色图 | `/camera_l` | `observations/images/cam_right_wrist` |
| 从臂实际角度 + 夹爪 | `/puppet/joint_*` | `observations/qpos` (400, 14) |
| **主臂角度**（= 人手的动作） | `/master/joint_*` | `action` (400, 14) |
| 速度 / 力矩 | `/puppet/joint_*` | `qvel` / `effort`（训练不用） |
| 底盘速度 | 固定 | `base_action` (400, 2) 全零 |

**训练学的是 `qpos + 两路图像 → action`**，也就是"看到这个画面和手臂状态，人手接下来会怎么动"。

同步规则：三路图像时间戳取最小值，四个关节消息的时间戳都必须 ≥ 该时刻，才凑成一帧。
所以任何一个话题没数据，就会一直打印 `syn fail`，一帧也录不进去。

## 二、开始之前

```bash
# 1) 环境（相机 → 机械臂，见 docs/02）
bash ~/cobot_magic/bringup.sh cams       # 终端 A

#    当前任务名：grasp_cube（固定位置，已有 51 条）
#    新数据集建议：grasp_cube_rand（10cm 随机位置）
```

## 三、录制：`record_here.sh`（推荐）

```bash
bash ~/cobot_magic/record_here.sh grasp_cube 0 400
#                              任务名      起始编号 每条帧数
```

交互：

| 按键 | 作用 |
|------|------|
| **空格** | 开始录这一条（从按下那一刻起录 400 帧 = 13.3 s） |
| **x** | 录制中随时取消，数据不落盘，编号不变 |
| **q** | 退出脚本 |

每条录完会自动质检：

- 通过 → `✅ episode_N 通过质检`，编号 +1
- 不通过 → 自动改名成 `episode_N.hdf5.bad_HHMMSS`，编号不变，提示你重录

已存在且合格的编号会自动跳过，所以中途退出再进来不会覆盖好数据。

> 另一个 `collect_timed.sh` 是"倒计时自动开录"版本（双手都占着时用），规则一样，只是不用按空格。
> 两者都支持 `x` 取消。

## 四、示范规范（按这个做，成功率差别很大）

一条 = **400 帧 = 13.33 秒**，时间轴这样分配：

```
0 ──────────── 4~6 s ──────────── 8~11 s ──────── 13.3 s
    张开靠近      夹住方块并抬起        送到盒子松手      保持静止
```

具体要求：

1. **每次从同一个起点姿态开始**。用 `move_home.py` 会把双臂推到"数据集里第一帧的中位数"，
   采集时你手动把臂摆回那个姿态即可（每次偏差别超过几度）。
2. **动作要连续、慢**，不要一顿一顿。策略学的是连续轨迹，急停急起会学成抖动。
3. **11 秒内做完动作**，最后留 **≤2 秒完全静止**。静止太久会被质检判为"长时间静止"。
4. **夹住后要确认夹稳**再抬（夹爪实测会停在 0.023~0.028，不是 0）。
5. **只保留成功的示范**。失败的那条按 `x` 取消，或让它质检失败自动改名。
6. **左臂全程别动**（质检要求左臂变化 < 0.05 rad）。
7. 手腕相机视野里要能看到方块和夹爪，别让方块跑到画面外。

## 五、采"10 cm 随机位置"数据集（下一阶段要做的事）

目标：让策略见过方块在小范围内各种位置的样子，从而泛化到随机摆放。
**只变位置，不变朝向**（方块始终摆正，与桌边平行）。

### 1) 打印方格纸

`docs/cube_grid_10cm.pdf` 是一张 **1:1 的 10 cm × 10 cm 方格**（5×5 = 25 个格点，间距 2 cm）。
打印时务必选「**实际大小 / 100%，不要缩放**」，打印后拿尺子量一下外框是不是正好 10 cm。

把它用胶带固定在桌面上，**方格中心对准原来那个固定抓取点**。

### 2) 格点命名

```
     1    2    3    4    5
  A  ·    ·    ·    ·    ·
  B  ·    ·    ·    ·    ·
  C  ·    ·    ·    ·    ·      ← 中心 C3 = 原来的固定抓取点
  D  ·    ·    ·    ·    ·
  E  ·    ·    ·    ·    ·
```

### 3) 采集方案（40 条）

- 25 个格点，每个至少 1 条 → 25 条
- 剩下 15 条：随机挑 15 个格点再采一遍（换一次落点精度，让同一格点也有 ±5 mm 的差异）
- **不要按 A1→E5 的顺序采**，把 40 个点打乱成一张随机顺序表，避免机械臂/你形成节奏记忆
- 每条都**保持方块朝向一致**（面和桌边平行）
- 起点姿态、盒子位置、松手位置全部不变，**只让方块的位置变**

> 为什么用格点而不是完全随机：格点保证覆盖均匀，事后能一眼看出哪块区域没采到。
> 完全随机会在中心扎堆、边角落空。

### 4) 采完检查"覆盖得够不够"

`check_spread.py` 会统计每条示范**夹住瞬间**的右臂姿态离散程度——这是"方块位置真的变了"的客观证据：

```bash
python3 ~/cobot_magic/check_spread.py ~/data/grasp_cube_rand
```

| 输出 | 含义 |
|------|------|
| 各轴 std | 夹住瞬间手臂姿态的离散度 |
| 参考值 | 旧数据集 51 条固定位置：**std 0.064 rad** |
| 目标 | 随机位置 40 条：std 明显大于 0.064（通常 0.1~0.3 rad，取决于 10 cm 范围） |

如果 std 还是 0.06 左右，说明你实际上没换位置，回去重采。

## 六、质检规则（自动执行，不通过就改名重录）

`check_act_data.py` 会逐条检查 8 项：

| # | 检查项 | 阈值 | 为什么 |
|---|--------|------|--------|
| 1 | 无残帧/野值 | 所有值 < 10 rad，逐帧跳变 < 0.5 rad | 偶发的 `J6=-292`、`夹爪=1895` 会把归一化 std 压扁，整维废掉 |
| 2 | 右臂运动足够 | 幅度 > 0.15 rad | 没动就学不到东西 |
| 3 | 右夹爪开合 | 范围 > 10 mm | 必须真的夹了东西 |
| 4 | 左臂静止 | 变化 < 0.05 rad | 保证"只有右臂干活" |
| 5 | 主从不相等 | 最大差 > 1e-3 | 相等说明录的是从臂自身，训出来是恒等映射 |
| 6 | base 全零 | —— | 本项目不用底盘 |
| 7 | 无长时间静止 | 静止帧 < 60（2 秒） | 采集时不要发愣 |
| 8 | 图像有效 | 每路 mean、std 都 > 5 | 全黑/全白说明相机没出图 |

手动对某一条或整批跑：

```bash
python3 ~/cobot_magic/check_act_data.py ~/data/grasp_cube            # 整批
python3 ~/cobot_magic/check_act_data.py ~/data/grasp_cube/episode_7.hdf5   # 单条
```

## 七、存储与核对

| 项 | 数值 |
|----|------|
| 单条大小 | 约 **700 MB**（400 帧 × 2 路 480×640×3 未压缩图像） |
| 40 条 | 约 **28 GB** |
| 51 条（现有） | 36 GB |

采完核对：

```bash
ls ~/data/grasp_cube_rand/episode_*.hdf5 | wc -l     # 条数
ls ~/data/grasp_cube_rand/*.bad_* 2>/dev/null | wc -l # 被改名的不合格条数
du -sh ~/data/grasp_cube_rand                         # 占多少空间
```

## 八、常见问题

| 现象 | 原因 / 处理 |
|------|------------|
| 一直打印 `syn fail`，录不进去 | 某个话题没数据。2 路相机时 `img_left` 必须指向 `/camera_l`（脚本已改好）；再查相机/关节频率 |
| 录完质检报"主从不相等 ❌" | `master` 和 `puppet` 数值一样，说明主臂没真正参与（主臂没上电/固件随动没开），**整批数据不能用** |
| 质检报"左臂静止 ❌" | 采集时左手碰到左臂了 |
| 质检报"无残帧 ❌" | 数据里有野值帧，直接重录那条 |
| 夹爪开合不足 10 mm | 没夹到方块就录了，或方块太小/夹爪坏了 |
| 录到一半发现做错了 | 按 `x`，这条不会保存 |
| 条数不是从 0 连续 | 正常，坏的会改名，编号空缺可手动补：改起始编号重录 |

---

## 九、小技巧

- **先空录一条试机**：确认 `syn fail` 不出现、质检能过，再正式采。
- 采 5 条先跑一次 `train_cube.sh`（10 epoch），能跑通说明数据格式没问题，再继续采。
- 每采 10 条跑一次 `check_act_data.py` 整批，别攒到最后发现要重来。
- 记住每条大 700 MB，采 40 条前先 `df -h`。
