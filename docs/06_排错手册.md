## A. 上电类

### A1 自动使能超时退出

**现象**：`bringup.sh arms 0/1` 之后，机械臂节点打印

```
程序自动使能超时,退出程序
```

然后进程退出，`/puppet/joint_*` 没有数据。

**原因**：节点启动后 5 秒内收不到 `driver_enable_status`。只有两种可能：

1. 臂没上电
2. CAN 没有报文（接口 DOWN、USB 松、波特率不对）

**处理**：

```bash
# 先看接口
ip -br link | grep can
ip -details link show can_right | grep bitrate

# 再看有没有报文（最可靠）
for c in can_right can_left; do
  a=$(cat /sys/class/net/$c/statistics/rx_packets); sleep 1
  b=$(cat /sys/class/net/$c/statistics/rx_packets)
  echo "$c: 1 秒 $((b-a)) 帧"
done
```

- 3000 帧/秒 → 通信正常，检查臂是否上电
- 0 帧/秒 → 重新 `bringup.sh can`，检查 USB-CAN 线

### A2 ROS master 没了

**现象**：`rostopic list` 超时，或者所有节点都报 `Unable to communicate with master`。

**原因**：ROS master 由**最先启动的那个 roslaunch** 兼任。通常是相机 launch（`bringup.sh cams`）。
如果那个终端被 Ctrl+C / 关掉 / 被 `pkill` 杀掉，master 就没了，机械臂节点也会跟着失联。

**处理**：按"异常恢复"重来（`docs/02` 第八节）：全部停 → 先起相机 → 再起机械臂。

**预防**：相机那个终端别关、别在里面按 Ctrl+C。要停就 `bringup.sh stop`。

### A3 CAN 接口正常但收不到报文

| 可能 | 检查 |
|------|------|
| 臂没开电源 | 电源指示灯 |
| 波特率配错 | `ip -details link show can_right \| grep bitrate` 应为 1000000 |
| USB-CAN 没插/插错口 | `lsusb`，或 `dmesg \| tail` 看有没有掉设备 |
| 另一个进程占着 CAN | `bringup.sh status` |

## B. 采集类

### B1 采集一直 syn fail

**现象**：`record_here.sh` 开录后终端一直刷 `syn fail`，帧数不涨，最后录出 0 帧。

**原因**：`get_frame()` 要求 **front / left / right 三路图像队列都非空**，且有 4 个关节消息。
任何一路没数据就永远凑不齐。

**排查**：

```bash
rostopic list | grep image_raw      # 应该只有 /camera_r 和 /camera_l
rostopic hz /camera_r/color/image_raw
rostopic hz /camera_l/color/image_raw
rostopic hz /puppet/joint_right
rostopic hz /master/joint_right     # mode=0 才有
```

**最常见的坑**：脚本里 `--img_left_topic` 指向了 `/camera_f`，但现在只有 2 路相机。
本项目的三个脚本（`record_here.sh` / `collect_timed.sh` / `bringup.sh`）已经改成指向 `/camera_l`。
如果你自己手拼命令，记得也要这么写。

### B2 质检"主从不相等"失败

**现象**：

```
❌ 主从不相等   max 0.000
```

**原因**：录进 HDF5 的 `action`（应是主臂/人手）和 `qpos`（从臂实际）完全一样。
说明主臂没上电、或固件没开随动，程序读到的是从臂自身数据。

**后果**：训出来的策略是"恒等映射"——输入什么角度就输出什么角度，实机上**一动不动**。

**处理**：主臂上电，重新 `bringup.sh check`，第 3 步必须看到 master 随你拖动变化。
这一批数据全部作废，重采。

## C. 训练类

### C1 训练爆显存

```
RuntimeError: CUDA out of memory
```

- 把 `--batch_size` 从 8 降到 4（或 6）
- 先 `nvidia-smi` 看有没有别的进程占着
- 不要改 `--backbone` 之外的模型结构参数

### C2 训练进程凭空消失

**现象**：日志停在某个 epoch，没有任何报错，进程没了。之前 v3 跑到 epoch 2249 就是这样。

**原因**（按概率）：

1. **终端/会话被清理**（最常见）——前台 `nohup` 不够，要 `setsid`
2. 系统 OOM killer（内存，不是显存）
3. 磁盘写满

**处理**：

```bash
# 正确姿势
setsid nohup bash ~/cobot_magic/train_cube.sh ... > /tmp/aloha_logs/train.log 2>&1 < /dev/null &

# 事后确认
dmesg -T | grep -i -E "oom|killed process" | tail
df -h ~
```

训练中断不怕，已有权重都在，可以从最近的 epoch 续训（`PRETRAIN=...`）。

### C3 `FileNotFoundError: episode_XX.hdf5`

`--num_episodes` 比真实条数大。数一遍：

```bash
ls ~/data/grasp_cube/episode_*.hdf5 | wc -l
```

`train_cube.sh` 会自动数，手工命令时容易写错。

### C4 磁盘满

每个权重 380 MB，3000 epoch 存 30 个 = 11 GB；数据每条 700 MB。
清理见 `docs/07`。

## D. 推理类

### D1 推理报"还在 mode=0"

```
❌ /master/joint_right 有发布者 → 机械臂还在 mode=0【采集模式】
```

**原因**：`/master/joint_*` 有发布者，说明机械臂节点还在 mode=0（主臂随动发布）。

**处理**：

```bash
bash ~/cobot_magic/bringup.sh armstop     # 停机械臂节点，相机不动
bash ~/cobot_magic/bringup.sh arms 1      # 以推理模式重启
# 并且：拔掉主臂电源
```

### D2 推理能动但动作明显不对

按可能性排序：

1. **起点不对**：没跑 `move_home.py`，或跑的时候臂被挡了。看启动日志"已到位：右臂残差 x rad"，应 < 0.1。
2. **主臂没断电**：主臂固件在同一个 `/master/joint_*` 通道上写，程序指令被覆盖。表现为动作"黏"、被拽。
3. **stats 和 ckpt 不匹配**：`dataset_stats.pkl` 必须和 ckpt 同一目录、同一次训练产生的。
4. **相机接反**：`cam_high` 必须是头视（`/camera_r`），`cam_right_wrist` 必须是右腕（`/camera_l`）。
   接反了策略会"看着错误的世界"动。
5. **左臂被挡住**：左臂目标虽然不变，但卡住会产生力矩，影响整体。

### D3 夹着方块不松手（抱回原位或半路掉）

**症状**：日志里实测一直 0.027（夹着），但 `右臂` 已经离开盒子，甚至回到原点，然后半路张开。

**原因**：模型的夹爪值没有给出释放峰，"到位释放"也没触发。

**处理**：

1. 先确认放置位参数对不对（盒子是不是挪过）：
   ```bash
   # 日志里"到位释放"那行的偏差值，> 0.25 就不会触发
   grep "到位释放" /tmp/aloha_logs/policy_run.log
   ```
2. 盒子挪过 → 重新算放置位（取新示教释放瞬间的中位数），或把 `--place_radius` 放宽到 0.30
3. 完全没打印任何 `到位释放` → 检查 `--place_pose` 是否与实际盒子位置差太多
4. 实在不行用兜底：让它停下来（静止 2 秒）时会触发 `静止兜底`

### D4 空夹（实测 0.000）

**症状**：`下发=0.0000 实测=0.0047`（或 0.000），然后抬起来什么也没有。

**原因**：

1. 方块不在抓取位（最常见，肉眼看）
2. 方块位置偏太多（当前模型只能抓固定位置，偏 > 2 cm 就悬）
3. 夹爪标定漂了（`grip_close` 下发 0 但夹不到）

**处理**：把方块放回示教位置；这是当前版本的固有限制，靠重训随机位置数据解决。

### D5 推理循环变慢

**症状**：日志 `墙钟 38.3s` 而 `t=28.5s`，即真实时间比策略时间快 30%+。

**原因**：单次前向 40 ms（25 Hz 上限），GPU/CPU 被抢占时会掉到 13 Hz。

**处理**：

```bash
nvidia-smi                     # 看有没有别的进程
ps aux --sort=-%cpu | head     # 看 CPU 占用
```

关掉浏览器/训练任务/其他 roslaunch。CPU 频率降到 powersave 也会有影响。

## E. 工具类

### E1 `pkill` 自杀陷阱（重要）

**现象**：执行类似

```bash
pkill -f inference.py
```

命令返回了，但**你自己这条 shell 命令也被杀了**（或者后续命令不执行）。

**原因**：`pkill -f` 匹配的是**完整命令行**。你这条命令的字符串里就包含 `inference.py`，
所以它匹配到了自己（以及父 shell）。

**正确写法**——用字符类打断字面匹配：

```bash
pkill -f "inference[.]py"        # 匹配 inference.py，但不会匹配 "inference[.]py" 这个字符串本身
pkill -f "[r]un_policy.sh"
pkill -f "roslaunch piper"       # 这个没问题，因为要杀的就是 roslaunch piper
```

**还要注意**：不要在**同一条命令里**同时写"要杀的模式"和"真实路径"，
比如 `pkill -f "act/inference.py"` 后面又 `cat act/inference.py`，后者也会被匹配。

**大范围杀伤**：`pkill -f ros`、`pkill -9 python` 会把相机节点、机械臂节点、你自己的脚本全带走，
然后 ROS master 消失，要按 A2 重来。**别用。**

### E2 后台进程消失

用 shell 工具/`&` 起的后台任务，在会话结束或服务器重启时会消失。

正确：

```bash
mkdir -p /tmp/aloha_logs
setsid nohup bash ~/cobot_magic/train_cube.sh ... > /tmp/aloha_logs/x.log 2>&1 < /dev/null &
```

三个要素：`setsid`（脱离会话）、`nohup`（忽略 SIGHUP）、`< /dev/null`（不占终端输入）。

### E3 sudo 密码

`bringup.sh can` 内部会 `sudo`，需要你在终端里输密码。
如果你的自动化环境没法交互输入，只能在**你自己的终端**里手动跑这一条。

检查当前是否能免密：

```bash
sudo -n true && echo "可以免密" || echo "需要密码"
```
