# 05 推理与实机运行

这篇讲：**怎么让训练好的策略在真机上跑起来，以及怎么看懂它在干什么。**

---

## 一、跑之前检查清单

| # | 检查 | 怎么确认 |
|---|------|---------|
| 1 | 相机 2 路都是 30 Hz | `rostopic hz /camera_r/color/image_raw` |
| 2 | 机械臂是 **mode=1**（推理模式） | `run_policy.sh` 会自己检查，报错就是没切 |
| 3 | **主臂断电** | 物理拔电源，否则会跟程序抢控制权 |
| 4 | 从臂已使能 | `bringup.sh status` |
| 5 | 方块在抓取位、盒子里空着 | 肉眼看 |
| 6 | 手放在急停上，工作区无人 | —— |

一条命令跑：

```bash
bash ~/cobot_magic/run_policy.sh ~/train_cube_v3 policy_epoch_2100_seed_0.ckpt
```

按回车后：双臂先**慢慢**移动到训练起点姿态（约 0.2 rad/s），然后策略开始动。

---

## 二、`run_policy.sh` 到底做了什么

```
① 检查权重文件存在
② 检查 ROS / 话题：/puppet/joint_left|right、/camera_r、/camera_l
③ 检查 /master/joint_right 有没有"发布者"
   —— 有 = 机械臂还在 mode=0（采集模式），直接拒绝运行
④ 调用 move_home.py：把双臂推到数据集第一帧的中位数姿态（每次都从同一姿态出发）
⑤ 启动 inference.py（30 Hz 闭环）
```

第 ④ 步很重要：**ACT 对起始姿态很敏感**。起点不同，策略的动作轨迹会完全不一样。所以每次都要回到同一个起点，结果才可复现。

参数：

```bash
bash run_policy.sh [权重目录] [权重文件名]
# 想一直循环不自动停：
STOP_AFTER_RELEASE=0 bash run_policy.sh ~/train_cube_v3 policy_epoch_2100_seed_0.ckpt
```

---

## 三、推理循环（每帧在干什么）

以 30 Hz 循环，每一帧：

```
1. 从队列里取"时间对齐"的一帧：两路图像 + 左右从臂 qpos（14 维）
2. qpos 用 dataset_stats.pkl 归一化 → 送进模型
3. 模型输出 32 帧 × 14 维的动作块
4. 时间集成：把历史预测按 exp(-0.01·i) 加权平均，取当前帧 → 反归一化成真实角度
5. 夹爪单独处理：连续值 → 两态（张开/闭合），再叠加两条兜底规则（见第四节）
6. 发布：左臂 7 维 + 右臂 7 维 → /master/joint_left|right → 从臂执行
```

第 5 步是所有"魔改"集中的地方，下一节单独讲。

## 四、夹爪的四条规则（为什么需要，怎么调）

模型输出的是**连续夹爪值**。但真实夹爪只有两种有意义的状态：张开、闭合到底。
下面四条规则把连续值变成可靠的动作。

### 规则 1：两态化（`decide_gripper`）

| 状态 | 触发条件 | 下发值 |
|------|---------|--------|
| 张开 → 闭合 | 本次张开以来的峰值回落 15%（`grip_close_frac=0.85`） | `0.0` |
| 闭合 → 张开 | 从谷值回升峰谷差的 35%（`grip_reopen_frac=0.35`） | `0.0685` |

**为什么不能让模型直接输出连续值**：示教里"搬运段"夹爪显示 `≈0.041`，那是**方块把爪子撑住时的测量值**，
不是目标值。操作员当时是把爪子一路夹到 0、靠力矩夹住方块。如果照抄 0.041 下发，等于"刚好贴住方块、零夹紧力"，
一碰就滑；到盒子处也张不到方块宽度之外，松不了手。

**为什么不能用固定阈值**：本机实测，靠近方块时的峰值是 0.071，到盒子处的释放峰只有 0.054，差 25%。
任何"绝对电平"都会把释放判丢。所以按**每次开合循环各自的峰谷**来算。

### 规则 2：到位释放（`place_pose`）—— 2026-11-03 新增

```
条件：夹爪处于闭合态 且 实测夹爪 > 18 mm（说明夹着东西）
     且 右臂 6 轴与"放置位"每轴偏差 < 0.25 rad
     且 持续 ≥ 1.0 秒
动作：强制张开，并保持张开 1 秒
```

放置位取的是 **51 条示范里能自动识别出"夹住→释放"的 49 条**、在"释放瞬间"右臂姿态的中位数：

```
(0.885, 2.030, -1.700, 0.264, 1.222, -0.698)
各轴标准差只有 0.03~0.06 rad，49 条里最坏偏离 0.21 rad
```

**为什么需要它**：模型偶尔会在盒子上方"抱着方块不松手"（输出一直停在夹住值，不给释放峰）。
实机遇到过：抱着方块飞回原位、掉在半路；或者停在盒子上方 20 秒不动。
有了这条规则，**只要夹着东西到了盒子位置，1 秒后必定松手**，不再依赖模型自己给释放峰。

### 规则 3：静止兜底（`dwell_release_check`）

```
条件：闭合态 + 实测 > 18 mm + 闭合后右臂移动过 ≥ 0.3 rad + 右臂静止 ≥ 2 秒
动作：强制张开
```

这是"策略收敛到某个姿态后彻底不动"时的最后保险。
注意它要求**完全静止**，而从臂在目标位置常有 0.1 rad/s 的残余速度，所以它经常等不到——
这正是新增"规则 2"的原因（规则 2 只看位置，不看静止）。

### 规则 4：自动停止（`--stop_after_release_sec`）

```
完成一次"夹住 → 松开"后，N 秒（默认 2）自动退出进程
设为 0 → 不停止，继续跑第二遍
```

**为什么默认 2 秒**：任务是一次性的。不停止的话，策略会接着执行第二遍——
方块已经在盒子里了，它却会跑回抓取位再"抓"一次空气。

想连续循环观察（比如测稳定性），用 `STOP_AFTER_RELEASE=0`。

## 五、日志怎么读

每 15 帧（0.5 秒）打一行：

```
  t= 5.00s 墙钟  5.0s 夹爪 模型=0.0364 → 下发=0.0000 实测=0.0281  (峰值 0.0540)  闭合 | 右臂 +0.64 +1.63 -1.05 +0.17 +0.99 -0.96 | 跟随偏差 0.01
```

| 字段 | 含义 | 怎么用 |
|------|------|--------|
| `t` | 策略内部时间（帧数/30） | 和示教时间轴对照 |
| `墙钟` | 真实经过秒数 | 明显大于 `t` 说明循环变慢（正常应接近相等） |
| `模型` | 模型原始输出的夹爪值 | 看它有没有给"释放峰" |
| `下发` | 两态化（+兜底）之后真正发出去的值 | `0.0685`=张开，`0`=闭合 |
| `实测` | 从臂反馈的真实夹爪开度 | **判断有没有夹到方块的关键** |
| `峰值` | 本轮张开以来的最大模型值 | 两态化判据用 |
| `闭合/张开` | 当前状态 | —— |
| `右臂` | 下发的右臂 6 轴目标 | 对照放置位 |
| `跟随偏差` | 实测与目标的每轴最大差 | < 0.1 正常；> 0.3 说明从臂跟不上（要停） |

### 实测夹爪值的语义（最有用的一条经验）

| 实测值 | 含义 |
|--------|------|
| `0.023 ~ 0.028` | **夹着方块**（方块宽 23 mm） |
| `0.060 ~ 0.068` | 空手张开 |
| `0.000` | 空手闭合（没夹到） |

### 三个真实片段

**① 成功（单轮）**

```
  t= 5.00s  ... 下发=0.0000 实测=0.0281  ... 闭合 | 右臂 +0.64 +1.63 -1.05 | 跟随偏差 0.01
  🔓 到位释放：放置位偏差 0.12 rad，持续 1.0s，实测夹爪 0.0266 → 强制张开
  🏁 检测到释放，2.0 秒后自动停止（要再跑请重新启动）
  🏁 已自动停止
```

**② 空夹（方块不在位）**

```
  t= 5.00s ... 下发=0.0000 实测=0.0047 ... 闭合     ← 夹了个空气
```

**③ 危险（抱着方块跑回去）**

```
  t=10.50s ... 实测=0.0276 ... 右臂 +0.91 +2.00 -1.79   ← 到盒子了
  t=18.00s ... 实测=0.0276 ... 右臂 +0.14 +0.51 -0.61   ← 还夹着，已经跑回原位！
  t=21.00s ... 实测=0.0656 ... 右臂 +0.55 +1.42 -1.06   ← 半路松开，方块掉了
```

出现第 ③ 种，说明"到位释放"没触发（偏差 > 0.25 或时间不够）。处理见第七节。

## 六、单轮 vs 连续循环

| 模式 | 命令 | 适用 |
|------|------|------|
| 单轮（默认） | `bash run_policy.sh ...` | 正式使用、统计成功率 |
| 连续循环 | `STOP_AFTER_RELEASE=0 bash run_policy.sh ...` | 观察行为、拍视频 |

**实测结论：连续循环第 2 回合起会退化。** 第一次跑连续模式时，第 1 回合就出现"到盒子不松手、抱回原位、
半路掉落"，第 2 回合又"停在盒子上方 20 秒不动"。原因：每一轮结束后手臂的实际状态和示教的起点越来越远，
模型越跑越偏。**要统计成功率，请用单轮模式（batch），不要用连续循环。**

## 七、批量测试 N 轮

```bash
bash ~/cobot_magic/run_trials.sh 10 20 ~/train_cube_v3 policy_epoch_2100_seed_0.ckpt
#                               轮数 间隔秒
```

它每轮：`run_policy.sh`（含 move_home）→ 自动停止 → 停 20 秒让你把方块放回抓取位。

跑完自动分析：

```bash
python3 ~/cobot_magic/analyze_trials.py
```

输出：

```
  轮     结果      夹住时刻      夹住实测      释放时刻       释放位置J1/J2/J3     方式
  1     ✅       5.0s    0.0281     10.2s  +0.94 +2.02 -1.72     到位
  2     ❌       5.5s    0.0047        -              -           -

总计 2 轮：夹到方块 2，完成释放 1，完整成功 1
```

判定口径：

- **夹住** = 下发闭合 且 实测在 0.018~0.045（排除刚闭合的过渡帧）
- **完整成功** = 夹住 + 检测到释放 + 释放位置接近盒子

> `analyze_trials.py` 只认 `run_trials.sh` 产生的带 `ROUND n` 标记的日志，
> 连续循环的日志没有轮次边界，会显示 0 轮。

## 八、已知限制（都是实测数据支撑的）

### 1. 方块位置一变就抓不到（最重要的限制）

51 条示教里，**夹住瞬间**右臂 6 轴的标准差只有 **0.064 rad**，末端约 **±1.3 cm**。
也就是说示教里方块几乎不动，模型数学上没机会学"位置变化 → 不同动作"。

- 离线指标也能看出来：右臂 MAE 0.0549 rad ≈ 1.1 cm
- 实测：偏 2 cm 以内还能勉强抓到；偏 5 cm 就失败

**解决办法只有改数据**：按 `docs/03` 第五节采 10 cm 见方的随机位置数据重训。

### 2. 连续循环会漂

见第六节。用单轮 batch。

### 3. 循环频率会波动（22~30 Hz）

单次前向约 40 ms，理论上限 25 Hz。实测会掉到 13 Hz（CPU/GPU 被抢占时），
表现为日志里 `墙钟` 明显大于 `t`。掉太多会让策略反应变慢，出现类似"犹豫"的动作。
跑之前用 `nvidia-smi` 确认没有别的任务在占 GPU。

### 4. 放置位是写死的

`--place_pose` 默认是当前盒子的位置。**盒子换了位置，必须改这个参数**（或重新算示教释放位）。

### 5. 左臂不动

数据里左臂一直静止，所以策略输出左臂"保持不动"。这是设计如此，不是 bug。

## 九、调参速查

| 参数 | 默认 | 什么时候改 |
|------|------|-----------|
| `--stop_after_release_sec` | 2.0 | `0` = 一直循环 |
| `--place_radius` | 0.25 | 松手太早/太浅 → 收到 0.18；始终不触发 → 放到 0.30 |
| `--place_hold_sec` | 1.0 | 盒子更高、想放低一点 → 1.3 |
| `--grip_reopen_frac` | 0.35 | 模型完全不给释放峰时，可降到 0.25 |
| `--grip_open` / `--grip_close` | 0.0685 / 0.0 | 换夹爪/换方块尺寸时重新标定 |
| `--publish_rate` | 30 | 一般不动（与示教帧率一致） |
| `--puppet_arm_*` | —— | 话题名，一般不动 |

改这些参数最好通过 `run_policy.sh` 传环境变量，或者直接改 `inference.py` 的默认值。
不要在命令行手拼一长串，容易漏参数导致行为不一致。

## 十、安全

1. **手始终放在急停上**，第一次跑新权重时尤其要这样。
2. 启动后先看 `move_home` 阶段：手臂应该**缓慢**移动（0.2 rad/s）。如果突然快速甩动，立即急停。
3. `跟随偏差` 持续 > 0.3 说明从臂跟不上或撞到东西，立刻停。
4. 不要在手臂运动时伸手去摆方块。
5. `Ctrl+C` 只会停止推理；从臂会停在当前位置（它不会自己回零）。
