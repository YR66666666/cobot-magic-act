## 一、硬件

| 部件 | 说明 |
|------|------|
| 机械臂 | AgileX Piper，共 4 条：左主臂（leader）、左从臂（puppet）、右主臂、右从臂 |
| 夹爪 | 每条臂末端 1 个，1 个自由度，可测开合角度 |
| 相机 | Dabai DC1 × 2（彩色，480×640，30 Hz）<br>序列号 `CC1S74100TL` → `/camera_r`（头视）<br>序列号 `CC1S74101HL` → `/camera_l`（右腕） |
| 底盘 | 移动底盘，本项目不用（`base_action` 全零） |
| 算力 | 工作站 + NVIDIA RTX 4060（8 GB），训练和推理都在这台机器上 |

主臂和从臂通过 CAN 总线连到同一台电脑：`can_left`、`can_right`，1 Mbps；底盘是 `can0`，500 kbps。

## 三、ROS 话题（谁发布、谁订阅）

| 话题 | 类型 | 频率 | 发布者 | 用途 |
|------|------|------|--------|------|
| `/puppet/joint_left`<br>`/puppet/joint_right` | JointState | 200 Hz | 机械臂节点（mode 0/1 都有） | **从臂实测值**，即 `qpos` |
| `/master/joint_left`<br>`/master/joint_right` | JointState | 200 Hz | mode=0：机械臂节点（主臂随动值）<br>mode=1：`inference.py`（策略指令） | 示教时是"人手的动作"，推理时是"给从臂的目标" |
| `/camera_r/color/image_raw` | Image | 30 Hz | 相机节点 | 头视 → `cam_high` |
| `/camera_l/color/image_raw` | Image | 30 Hz | 相机节点 | 右腕 → `cam_right_wrist` |
| `/camera_f/color/image_raw` | — | — | **当前不存在** | 左腕相机没装/没起，别去找它 |

**关键点：`/master/joint_*` 这个同名话题在两种模式下含义相反**：

```
采集 mode=0：  人手 → 主臂 → 节点发布 /master/joint_*  →  collect_data.py 记录为 action
推理 mode=1：  inference.py → 发布 /master/joint_*  →  从臂跟随执行
```

所以**推理时主臂必须断电**。否则主臂固件也在写这个通道，两边打架，从臂会被来回拽。

## 四、两种运行模式

`bringup.sh arms <mode>` 实际执行的是 `roslaunch piper start_ms_piper.launch mode:=<mode>`。

### mode=0 采集

```
        手拖
         ↓
   ┌─────────┐         ┌─────────┐
   │ 主臂     │  机械耦合 │ 从臂     │
   │ leader  │ ───────→ │ puppet  │
   └────┬────┘  跟随     └────┬────┘
        │ 发布                 │ 发布
   /master/joint_*        /puppet/joint_*
        │                     │
        └────────┬────────────┘
                 ↓
        collect_data.py
        action = master（人手）
        qpos   = puppet（实际）
```

主臂上电后，固件会让从臂实时跟随主臂（这就是"遥操作"）。程序**只读不控**。

### mode=1 推理

```
   inference.py
        │ 发布目标角度
        ↓
   /master/joint_*
        │
   ┌────┴────┐
   │ 从臂     │ ← 订阅并执行
   │ puppet  │
   └────┬────┘
        │ 发布实测
        ↓
   /puppet/joint_* → inference.py 读回来当下一帧的 qpos
```

主臂断电（不参与），从臂彻底由程序控制。

## 五、数据流：采集 → 训练 → 推理

```
【采集】30 Hz，每条 400 帧 = 13.3 s
  /camera_r 图像 ─┐
  /camera_l 图像 ─┼→ collect_data.py → ~/data/grasp_cube/episode_N.hdf5 （约 700 MB/条）
  /puppet  qpos ──┤        │
  /master  action ┘        └ 同步规则：三路图像时间戳取最小值，四个关节消息都必须 ≥ 该时刻
                                 （所以任何一个话题断了，就会一直打印 syn fail，录不进去）

【训练】
  episode_*.hdf5 ──→ train.py
                       ├─ 计算归一化统计 dataset_stats.pkl（qpos/action 的均值方差）
                       ├─ 8:2 按"条"随机分训练/验证
                       └─ 每 100 epoch 存 policy_epoch_N_seed_0.ckpt（380 MB）
                                     │
                                     ↓
【推理】                    ckpt + dataset_stats.pkl（必须成对使用！）
  /camera_r ─┐
  /camera_l ─┼→ inference.py：qpos 归一化 → ACT → 反归一化 → 夹爪两态化 → 发布
  /puppet ───┘        ↑ 每帧一次，约 30 Hz（单次前向 ~40 ms）
```

`dataset_stats.pkl` 必须和 ckpt 放在同一个目录。换了数据重训，stats 会跟着变；用旧 stats 配新 ckpt（或反过来）会导致动作整体偏移，是最隐蔽的坑之一。

## 六、维度约定（务必记牢）

模型输入输出都是 **14 维**：

| 索引 | 含义 | 备注 |
|------|------|------|
| 0–5 | 左臂 J1–J6 | 单位 rad |
| **6** | **左夹爪** | 单位 m（夹爪开合量） |
| 7–12 | 右臂 J1–J6 | 单位 rad |
| **13** | **右夹爪** | 单位 m |

- `qpos[7:14]` = 右臂 7 维（含夹爪），代码里右臂动作就是取这一段。
- 左臂虽然不干活，但**维度必须保留 14**：模型结构、归一化、ckpt 都按 14 维固定。

## 七、夹爪标定（实测）

| 状态 | 数值 | 说明 |
|------|------|------|
| 全闭 | `0.000` | 两爪尖相碰，靠力矩限幅夹住物体 |
| 夹住方块 | `0.023 ~ 0.028` | 方块 2.3 cm 见方，被夹住时爪子停在这个宽度 |
| 全开 | `0.060 ~ 0.0685` | 程序下发时用 `0.0685` |

**判断有没有夹到东西，就看实测夹爪值**：

- `≈0.023~0.028` → 夹着方块（最可靠的证据）
- `≈0.060+` → 空手张开
- `≈0.000` → 空手闭合（没夹到）

示教数据里"搬运段"的夹爪值是 `≈0.041`，那是**被方块撑住的测量值**，不是指令值。所以推理时不能照抄模型输出的连续值，必须两态化——详见 `docs/05` 第三节。

## 八、相机映射（踩过坑，务必按这个来）

| 物理位置 | ROS 话题 | ACT 里的名字 | 是否入模型 |
|----------|----------|--------------|-----------|
| 头部前方 | `/camera_r/color/image_raw` | `cam_high` | ✅ |
| 右腕末端 | `/camera_l/color/image_raw` | `cam_right_wrist` | ✅ |
| 左腕（无） | `/camera_f/...` | `cam_left_wrist` | ❌ 没接 |

`collect_data.py` / `inference.py` 的 `get_frame()` 会检查 **front/left/right 三个图像队列都非空**才放行（为了时间同步）。现在只有 2 路相机，所以 `img_left` 话题也指向 `/camera_l`——它只参与同步判断，不会存进数据（`camera_names` 里没有 `cam_left_wrist`）。

如果哪天重新装回左腕相机，把三个脚本里的 `--img_left_topic` 改回 `/camera_f/...` 即可。

## 九、时间尺度（写代码和调参时的参考）

| 量 | 数值 |
|----|------|
| 相机帧率 | 30 Hz（33 ms/帧） |
| 关节话题 | 200 Hz（5 ms/帧） |
| 一条示范 | 400 帧 = 13.33 s |
| 示教动作节奏 | 约 4.5~6 s 夹住，8~11 s 到达盒子松手，最后 2 s 静止 |
| 训练速度 | 约 2.5 s / epoch（51 条，batch 8，RTX 4060） |
| 推理速度 | 单次前向 ~40 ms，整套循环实测 22~30 Hz |
| 方块尺寸 | 2.3 cm 见方 |
| 当前抓取位置重复性 | 51 条示教夹住瞬间右臂 6 轴标准差 0.064 rad ≈ 末端 ±1.3 cm |
